# Daily Worklog

개발 작업의 흐름과 산출물을 기록하기 위한 공개용 문서 저장소입니다.

이 저장소에는 특정 회사나 서비스에 종속된 소스 코드, 내부 API 정보, 인증 정보, 사내 업무 데이터가 포함되지 않습니다.

## 개발 목적

반복적인 개발 업무에서 다음 과정을 정리하고 자동화하는 방법을 검토했습니다.

- 로컬 작업 증거 수집
- 일일 작업 초안 작성
- 생성된 산출물 검토
- 사용자 승인 및 보류 처리
- 승인된 항목만 외부 시스템에 반영
- 동일 항목의 중복 처리 방지

## 주요 설계 방향

### Local-first

작업 증거와 초안은 우선 로컬에 저장합니다. 사용자가 검토하기 전에는 외부 시스템에 변경을 발생시키지 않습니다.

### 대화형 승인

산출물이 준비되면 사용자가 항목별로 승인 또는 보류를 선택합니다.

예시:

```text
1 승인, 2 보류
```

승인된 항목만 다음 단계로 진행하고, 보류하거나 응답하지 않은 항목은 처리하지 않습니다.

### 명시적 작업 경계

자동화 작업은 초안과 검토 문서 생성까지만 수행합니다. 외부 시스템에 데이터를 반영하는 작업은 사용자의 승인 이후에만 수행합니다.

### 중복 처리 방지

각 작업 항목에는 고유 식별자와 검증용 digest를 부여하여 다음 상황을 방지합니다.

- 동일 산출물의 중복 제출
- 검토 이후 변경된 산출물의 제출
- 만료된 승인 결과의 사용
- 다른 항목에 대한 승인 정보의 오사용

## Codex Plugin으로의 확장

반복 작업을 Codex와 대화형으로 처리할 수 있도록 다음 개념을 Plugin 구조로 정리했습니다.

```text
Plugin 설정
  → 스케줄러 설정
  → 작업 산출물 생성
  → 검토 필요 알림
  → 사용자 승인/보류 응답
  → 승인된 항목 처리
  → 결과 확인
```

최종 사용자는 저장소를 직접 수정하지 않고, Plugin 설치 후 대화를 통해 설정과 검토를 진행하는 것을 목표로 합니다.

## Windows Scheduler 연동

Windows 작업 스케줄러는 다음 역할만 수행하도록 설계했습니다.

- 정해진 시간에 작업 실행
- 로컬 작업 증거 수집
- 일일 초안 생성
- 검토 문서 생성
- 검토 대기 상태 기록

스케줄러가 사용자 승인 없이 외부 시스템에 데이터를 제출하지 않도록 책임을 분리합니다.

## 공개 저장소의 범위

이 저장소는 구현 결과와 설계 방향을 설명하기 위한 공개 기록입니다.

포함하지 않는 내용:

- 회사명 및 사내 프로젝트명
- 내부 서비스 주소
- 내부 API 경로와 요청 계약
- AccessToken 또는 인증정보
- 실제 업무 태스크와 작업 내용
- 사내 저장소 주소
- 개인별 로컬 경로
- 사내 배포 및 운영 절차

## 상태 흐름

작업 항목은 다음과 같은 상태로 관리할 수 있습니다.

```text
PENDING
APPROVED
HELD
SUBMITTED
ALREADY_SUBMITTED
EXPIRED
INVALID
```

기본 원칙은 다음과 같습니다.

- `PENDING` 항목만 검토 대상
- `APPROVED` 항목만 처리 가능
- `HELD` 항목은 처리하지 않음
- `SUBMITTED` 항목은 중복 처리하지 않음
- `EXPIRED` 항목은 처리하지 않음
- `INVALID` 항목은 검증 후 재검토

## 보안 원칙

- 인증정보를 문서와 소스에 저장하지 않음
- 원시 작업 로그와 대화 내용을 공개 저장소에 기록하지 않음
- 외부 변경 작업 전에 사용자 승인 확인
- 산출물 변경 여부 검증
- 동일 작업의 중복 처리 방지
- 공개 저장소에는 일반화된 설명과 구조만 기록

## 목적

이 저장소의 목적은 특정 시스템의 사용법을 공개하는 것이 아니라, 다음과 같은 개발 작업을 어떻게 구조화했는지 기록하는 것입니다.

> 작업 증거를 모으고, 초안을 만들고, 사용자의 검토와 승인을 거친 뒤 필요한 작업만 안전하게 반영하는 흐름
